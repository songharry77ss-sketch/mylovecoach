# AI 비용 — 측정과 결정

## 지금 설정 (2026-10-10)

| 모드 | 모델 | 처리 등급 | 캡처 해상도 |
|---|---|---|---|
| 코칭 | gemini-3.6-flash (Vercel 환경변수 `GEMINI_MODEL`) | 일반 | MEDIUM |
| 보고서·속마음·연습 | gemini-3.6-flash | **Flex 먼저** — 8초 안에 답이 없거나 밀려나면(503 등) 일반으로 다시 | - |

- Flex 는 **같은 모델을 반값**에 쓰는 구글 등급이다. 모델이 같아 답 품질은 같고, 대신 붐비면 늦거나 밀려난다(공식 목표 1~15분, 503·429).
- 「Flex 먼저」는 `src/lib/gemini.ts` 의 `flexFirstMs`. 거절·형식 오류는 등급을 바꿔도 같아 다시 부르지 않는다. 앱이 끊으면 그대로 끊는다.
- 서버 스위치 (`api/_ai-flags.ts`)
  - `GEMINI_FLEX_MODES` — 모드 목록(`coach,report,mind,practice`)·`all`·`none`. 비우면 기본 `report,mind,practice`. **문제가 생기면 `none` 으로 바로 끈다** (Vercel 환경변수 + 재배포).
  - `GEMINI_FLEX_WAIT_MS` — 2000~30000, 기본 8000.
- 결과 확인: Vercel 로그의 `"log":"coach_api"` 줄에 `flex` 가 `served`(반값으로 처리) 또는 `fallback:timeout`·`fallback:http 503`(일반으로 다시), `flexMs` 가 기다린 시간이다. `served` 비율이 낮거나 `flexMs` 가 길면 기다릴 시간을 줄이거나 그 모드를 뺀다.

- 같은 모델이라 Flex 답과 일반 답은 같은 수준이었다. 속마음 Flex 답 하나에 한자(「督促」)가 섞였는데, 모델 자체의 드문 실수라 등급과는 무관하다고 본다.

## 프롬프트 캐싱을 쓰지 않는 이유

- 3.5~3.8 Flash 는 요청 앞부분이 **4,096토큰 이상 같아야** 캐시가 적용된다(적용 시 그 부분 90% 할인). 코칭의 고정 지시문은 약 1,200~1,500토큰, 요청 전체도 약 3,000토큰이라 문턱에 못 미친다. 실측에서도 3.6 Flash 캐시 토큰은 0.
- 억지로 4,096토큰까지 늘려 명시적 캐시를 쓰면 보관료(시간당 100만 토큰당 $0.50, 1월부터 $1.00)를 넘으려면 하루 코칭 약 70회 이상이 필요하고, 다른 모드는 오히려 비싸진다.
