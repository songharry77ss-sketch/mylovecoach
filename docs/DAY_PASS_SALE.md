# 하루 이용권 타임 세일 (2026-11-06 회의)

## 2026-11-07 결정과 일정

- **정가 ₩3,900** (이전 ₩2,700) — 2026-11-07 20:45쯤(KST) 두 스토어 가격을 바꿨다 (`node tools/price-change.mjs --product mylovecoach.pass.day --price 3900 --apply`). 서버 매출 상수(`FALLBACK_PRICES.day`)·약관·Play 설명도 같은 날 반영(PR #64).
- **특가 ₩2,900** (`DAY_SALE_PRICE_KRW = 2900`, 할인율 25%).
- **특가는 2026-11-28 00:00(KST) 이후에 연다.** 할인 전 가격(취소선)은 「최근 상당 기간(과거 20일 정도) 실제 판매가 중 가장 낮은 값」이어야 한다(공정위 「부당한 표시·광고 행위의 유형 및 기준 지정고시」, 대법원 2022.4.28. 2019두36001). 11-07 전에는 ₩2,700 에 팔았으므로 그 전에 「₩3,900 → ₩2,900」을 보이면 거짓 할인이다.
- 1.1.0 이상 앱은 **스토어에 특가 상품이 생기는 순간** 세일을 보여 준다 → 상품을 여는 시점이 곧 세일 시작이다.
  - **Android**: 11-28 이후 `node tools/day-sale-products.mjs --android --apply --price 2900` (만들면 바로 활성).
  - **iOS**: 소모성 상품은 이미 승인된 종류(하루 이용권)가 있어 **앱 버전 없이 상품만 따로 심사**에 낼 수 있다(Apple 도움말 「Submit an In-App Purchase」 — 처음 내는 종류만 새 버전과 함께). 승인되면 바로 팔리므로 **11-27 20:45(KST, 정가 인상 20일) 이후** `node tools/day-sale-products.mjs --ios --apply --price 2900` 로 만들고 상품 심사를 낸다(보통 1~2일 → 11-28~29 에 열림). 1.1.1(1년권)과 함께 내지 않는다 — 1.1.1 이 나가는 순간 열려 버린다.
  - 심사용 스크린샷: `docs/store-assets/iap-review-paywall-sale.png` (웹 미리보기로 찍은 「3,900원 → 2,900원」 결제 화면, 786×1704).

회의 메모 「000님을 위한 하루 무제한 이용권 / 타이머 들어가고 타임 세일」을 **정직하게** 구현했다.
표시광고법·전자상거래법(다크 패턴) 때문에 가짜 할인·가짜 카운트다운은 쓰지 않는다.

## 화면 (src/app/paywall.tsx)

- 맨 위 주인공 카드 「{이름}님을 위한 하루 무제한 이용권」(이름이 없으면 「오늘 하루 무제한 이용권」).
- 「지금 시작하면 내일 오후 3:42까지 무제한」 — 지금 사면 실제로 끝나는 시각(이용 중이면 이어 붙인 시각, 1분마다 갱신).
- 세일 중이면 「특가 마감까지 12:34」(1초마다), 취소선 정가 → 특가, 할인율(두 가격 숫자로 계산해 내림).

## 세일 규칙 (src/lib/billing/sale.ts — 순수 함수, src/__tests__/billing-sale.test.ts·paywall-sale.test.tsx)

| | |
| --- | --- |
| 여는 조건 | 스토어가 **특가 상품과 정가 하루 이용권을 둘 다** 확인했고, 두 가격을 숫자로 비교해 특가가 더 쌀 때. 프리미엄·팀원·하루 이용권 이용 중이면 열지 않음 |
| 시작 | 위 조건에 맞는 결제 화면을 **처음 볼 때** 한 번 (`saleOfferStartedAt` 저장 — 다시 열어도·앱을 껐다 켜도 처음부터 돌지 않음) |
| 길이 | **30분**. 끝나면 정가로 돌아가고 특가 상품은 살 수 없음. 화면 안내: 「특가는 7일에 한 번, 30분 동안 열려요」 |
| 쉬는 기간 | 끝난 뒤 **7일** 동안 다시 열리지 않음 → 그 뒤 처음 조건에 맞는 결제 화면에서 다시 30분 |
| 가격 | 취소선 = 스토어가 주는 정가 하루 이용권 가격, 특가 = 스토어가 주는 특가 상품 가격 (앱에 숫자를 적어 두지 않음) |
| 시계 | 남은 시간은 30분을 넘지 않는다(기기 시계를 되돌려도). 마감 순간 화면이 정가로 바뀐다. 특가가 보이던 채로 눌렀는데 그 사이 마감이 지났으면 정가 결제창을 열지 않고 「특가가 방금 끝났어요」를 보여 준 뒤 정가 화면으로 |
| 통화 | 두 상품 모두 통화를 알고 같을 때만 (한쪽이라도 모르면 열지 않음) |

## 상품

| 상품 ID | 종류 | 가격 | 효과 |
| --- | --- | --- | --- |
| `mylovecoach.pass.day.sale` | 소모성 (iOS) / 일회성 상품 (Play, 앱이 소비) | **₩2,900 (2026-11-07 결정)** — 정가 ₩3,900 보다 싸야 함 | 하루 이용권과 같음 (24시간 무제한, 자동 결제 없음, 이 기기에서만) |

앱(`planOfProduct`)·결제 처리(`iap.ts`)·서버 알림(`api/_store.ts`·`store-google.ts`·`store-apple.ts`)·어제 리포트(`api/daily-report.ts`)·결제 흐름 알림(`api/_funnel-alert.ts`)은 이 상품을 **하루 이용권(plan `day`)으로 인정**하고 이름만 「하루 이용권 특가」로 구분한다.

## 스토어에 만들 때 (사장님이 가격을 정한 뒤)

1. 가격 확정 (상품 ID 는 한 번 만들면 다시 못 쓴다).
2. **가격 상수 먼저**: `src/lib/billing/plans.ts` 의 `DAY_SALE_PRICE_KRW` 를 그 가격으로 고쳐 서버를 배포한다 — Google 실시간 알림에는 금액이 없어 서버가 이 값으로 매출을 적는다. 이 값이 비어 있는 동안 Android 특가 결제는 리포트·알림에 「금액 미정」으로 찍히고 매출 합계에서 빠진다(건수는 센다). `--apply` 는 이 값이 `--price` 와 다르면 멈춘다.
3. 확인만: `node tools/day-sale-products.mjs --price 1900` (기본 dry-run — GET 만, 아무것도 안 바꿈. 가장 가까운 App Store 가격대도 보여 줌).
4. **App Store 심사용 스크린샷**: 소모성 상품은 심사용 캡처가 없으면 「제출 준비 완료」가 되지 않는다. 특가가 보이는 결제 화면을 특가 지원 빌드(TestFlight)에서 찍어 `docs/store-assets/iap-review-paywall-sale.png` 로 둔다.
5. 만들기: `node tools/day-sale-products.mjs --apply --price 1900` (한쪽만: `--ios` / `--android`).
6. **App Store**: 처음 내는 소모성 상품은 **새 앱 버전과 함께** 심사에 올려야 한다 — App Store Connect 웹 → 버전 페이지 「앱 내 구입 및 구독」에서 「하루 이용권 특가」를 고른다(API 불가, `asc-listing.mjs --submit` 은 상품이 묶음에 없으면 멈춘다).
7. **Play**: 만들면 바로 활성. 앱은 특가 지원 빌드부터 세일을 보여 준다 (예전 빌드는 이 상품을 묻지 않으니 영향 없음).
8. 이용약관(`site/terms.html`)의 하루 이용권 항목에 「기간 한정 특가(앱에 표시된 가격·마감 시각)로 살 수 있고 효과는 같다」 한 줄 추가.
9. Play 가격과 App Store 가격대가 다르면(애플에 같은 가격대가 없을 때) 두 스토어 가격이 달라진다 — 앱은 스토어가 준 가격을 그대로 보여 준다.

## 이용 기록 (track)

- `sale_offer_start` `{ reason }` — 세일 30분이 시작됨 (기기당 7일에 한 번)
- `sale_offer_view` `{ reason, left }` — 이번 방문에서 세일을 봄 (남은 초)
- `sale_offer_missed` `{ reason }` — 특가 화면에서 눌렀는데 그 사이 마감됨 (결제창 안 열림)
- `purchase_start`·`purchase_*` `{ plan: 'day', sale: true }` — 특가로 결제 (정가는 `sale` 없음)
- `paywall_close` `{ …, sale: true }` — 세일을 보고 결제 없이 닫음
