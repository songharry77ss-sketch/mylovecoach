# 하루 이용권 타임 세일 (2026-11-06 회의)

회의 메모 「000님을 위한 하루 무제한 이용권 / 타이머 들어가고 타임 세일」을 **정직하게** 구현했다.
표시광고법·전자상거래법(다크 패턴) 때문에 가짜 할인·가짜 카운트다운은 쓰지 않는다.

## 화면 (src/app/paywall.tsx)

- 맨 위 주인공 카드 「{이름}님을 위한 하루 무제한 이용권」(이름이 없으면 「오늘 하루 무제한 이용권」).
- 「지금 시작하면 내일 오후 3:42까지 무제한」 — 지금 사면 실제로 끝나는 시각(이용 중이면 이어 붙인 시각, 1분마다 갱신).
- 세일 중이면 「특가 마감까지 12:34」(1초마다), 취소선 정가 → 특가, 할인율(두 가격 숫자로 계산해 내림).

## 세일 규칙 (src/lib/billing/sale.ts — 순수 함수, src/__tests__/billing-sale.test.ts·paywall-sale.test.tsx)

| | |
| --- | --- |
| 여는 조건 | 스토어가 **특가 상품과 정가 하루 이용권을 둘 다** 확인했고, 두 가격을 숫자로 비교해 특가가 더 쌀 때. 프리미엄·팀원·하루 이용권 이용 중이면 열지 않음 |
| 시작 | 위 조건에 맞는 결제 화면을 **처음 볼 때** 한 번 (`saleOfferStartedAt` 저장 — 다시 열어도·앱을 껐다 켜도 처음부터 돌지 않음) |
| 길이 | **30분**. 끝나면 정가로 돌아가고 특가 상품은 살 수 없음 |
| 쉬는 기간 | 끝난 뒤 **7일** 동안 다시 열리지 않음 → 그 뒤 처음 조건에 맞는 결제 화면에서 다시 30분 |
| 가격 | 취소선 = 스토어가 주는 정가 하루 이용권 가격, 특가 = 스토어가 주는 특가 상품 가격 (앱에 숫자를 적어 두지 않음) |
| 시계 | 남은 시간은 30분을 넘지 않는다(기기 시계를 되돌려도). 마감 순간 화면이 정가로 바뀌고, 결제 버튼은 누르는 순간 특가가 열려 있을 때만 특가 상품을 산다 |

## 상품

| 상품 ID | 종류 | 가격 | 효과 |
| --- | --- | --- | --- |
| `mylovecoach.pass.day.sale` | 소모성 (iOS) / 일회성 상품 (Play, 앱이 소비) | **예: ₩1,900 (사장님 결정 필요)** — 정가 ₩2,700 보다 싸야 함 | 하루 이용권과 같음 (24시간 무제한, 자동 결제 없음, 이 기기에서만) |

앱(`planOfProduct`)·결제 처리(`iap.ts`)·서버 알림(`api/_store.ts`·`store-google.ts`·`store-apple.ts`)·어제 리포트(`api/daily-report.ts`)·결제 흐름 알림(`api/_funnel-alert.ts`)은 이 상품을 **하루 이용권(plan `day`)으로 인정**하고 이름만 「하루 이용권 특가」로 구분한다.

## 스토어에 만들 때 (사장님이 가격을 정한 뒤)

1. 가격 확정 (상품 ID 는 한 번 만들면 다시 못 쓴다).
2. 확인만: `node tools/day-sale-products.mjs --price 1900` (기본 dry-run — GET 만, 아무것도 안 바꿈. 가장 가까운 App Store 가격대도 보여 줌).
3. **App Store 심사용 스크린샷**: 소모성 상품은 심사용 캡처가 없으면 「제출 준비 완료」가 되지 않는다. 특가가 보이는 결제 화면을 특가 지원 빌드(TestFlight)에서 찍어 `docs/store-assets/iap-review-paywall-sale.png` 로 둔다.
4. 만들기: `node tools/day-sale-products.mjs --apply --price 1900` (한쪽만: `--ios` / `--android`).
5. **App Store**: 처음 내는 소모성 상품은 **새 앱 버전과 함께** 심사에 올려야 한다 — App Store Connect 웹 → 버전 페이지 「앱 내 구입 및 구독」에서 「하루 이용권 특가」를 고른다(API 불가, `asc-listing.mjs --submit` 은 상품이 묶음에 없으면 멈춘다).
6. **Play**: 만들면 바로 활성. 앱은 특가 지원 빌드부터 세일을 보여 준다 (예전 빌드는 이 상품을 묻지 않으니 영향 없음).
7. `src/lib/billing/plans.ts` 의 `DAY_SALE_PRICE_KRW` 를 같은 가격으로 고쳐 서버 배포 — Google 실시간 알림에는 금액이 없어 서버가 이 값으로 매출을 적는다(그 전에는 금액 없이 알림).
8. 이용약관(`site/terms.html`)의 하루 이용권 항목에 「기간 한정 특가(앱에 표시된 가격·마감 시각)로 살 수 있고 효과는 같다」 한 줄 추가.
9. Play 가격과 App Store 가격대가 다르면(애플에 같은 가격대가 없을 때) 두 스토어 가격이 달라진다 — 앱은 스토어가 준 가격을 그대로 보여 준다.

## 이용 기록 (track)

- `sale_offer_start` `{ reason }` — 세일 30분이 시작됨 (기기당 7일에 한 번)
- `sale_offer_view` `{ reason, left }` — 이번 방문에서 세일을 봄 (남은 초)
- `purchase_start`·`purchase_*` `{ plan: 'day', sale: true }` — 특가로 결제 (정가는 `sale` 없음)
- `paywall_close` `{ …, sale: true }` — 세일을 보고 결제 없이 닫음
