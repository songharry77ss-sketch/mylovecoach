**파란 빛 그림자**, **떠다니는 3D 그림**, **아이콘 타일 반복**, **굵기 800·900 의 큰 숫자 여러 개**, **칩 앞 이모지**였다. 그래서:

### 색
- 흰 바탕(`theme.background`) + 무채색 회색 면(`theme.surface` #F4F4F6) + 거의 검정 글자(`theme.text` #141518). 카드 화면(마이·설정)만 아주 옅은 보랏빛 `theme.canvas`(11/12 회의 9번).
- 색은 **센딧 파랑 한 가지를 단색으로**, 화면의 한두 곳에만: ① 화면의 주요 버튼 하나(`GradientButton` — 이름만 그대로, 지금은 단색) ② 핵심 숫자 ③ 누를 수 있는 글자·진행 중 표시.
- `Brand.gradient`·`button`·`orb` 값은 이제 같은 색 세 번(=단색). **새 코드에서 `LinearGradient`·`BrandGradient`·`HeroCard` 를 쓰지 않는다.** 큰 색 면 대신 회색 면 카드.
- 그림자 없음(`CardShadow`·`BrandShadow` 는 빈 값). 떠 있는 조작부(탭 바·새 채팅 버튼)만 무채색 아주 옅게(`FloatShadow`).
- 내 말풍선 = 옅은 라벤더 블루 `theme.bubbleUser` + 검정 글자. 코치 말·결과 = 회색 말풍선(`theme.surface`) 안 흰 카드.
- 고른 칩 = 검정 채움 + 흰 글자(`Chip` 이 알아서). 칩·라벨 앞 이모지 금지(AI 가 만든 답장 속 이모지는 그대로).

### 글자
- 굵기는 700(제목·숫자) · 600(줄 제목·버튼) · 400(본문) 세 가지. 800·900 금지.
- 가장 큰 제목 24~28pt(`Typography.hero` 28). 한 화면(카드)에 큰 숫자는 **하나**(28pt 안팎), 나머지 숫자는 15~17pt.
- 한글 줄바꿈은 `AppText` 가 단어 단위로 한다(웹 keep-all, iOS hangul-word) — 직접 `Text` 를 쓰면 같은 처리를 넣는다.
- 읽어야 하는 글은 `textSecondary`(5.9:1) 이상. `textTertiary`(4.5:1)는 자리 글·시각 정도.

### 모양
- 모서리: 말풍선 22(이어지는 쪽 6) · 카드 20~24 · 큰 시트 28 · 버튼 16 · 그 밖 알약.
- **아이콘 타일(옅은 파랑 둥근 사각 + 파란 아이콘)을 줄마다 두지 않는다.** 줄 왼쪽 그림은 사람(얼굴 원)이나 내용이 있을 때만, 아이콘이 필요하면 회색 선 아이콘 하나.
- 얼굴 원(`Avatar`·`RoomAvatar`)은 한 가지 색(옅은 파랑 + 파란 글자), 둥근 원.
- 3D 그림(`Icon3D`)은 떠다니지 않는다(`float` 는 무시됨). 빈 화면 같은 곳에 꼭 필요할 때만.
- 칩·버튼·배지에 「인기」「1위」처럼 근거 없는 말 금지. 배지는 사실만(「자동 결제 없음」).

### 움직임
- 등장은 짧게(FadeInDown 280~320ms). 튕김·반짝이·숫자 세기는 **결과 도착·복사·결제 완료의 순간에만**. 빛 스침(shine)·떠다니기 없음.

### 화면 짜임 (피클 네 가지로 모은다)
1. 대화형 — 말풍선 + 회색 결과 카드(안에 흰 카드, 키-값 줄, 검정 「복사」 알약)
2. 목록형 — 흰 바탕 위 줄(얼굴 원 + 이름 + 한 줄 + 오른쪽 값), 카드·그림자 없이
3. 제안형 — 제목 + 짧은 본문 + 구분선
4. 카드형 — 옅은 바탕 + 흰 카드(설정·마이)

### 결제
- 결제 화면은 한 화면: 제목 한 줄 + 사실 한 줄 → (막힌 게 아니면) 얻는 것 체크 세 줄 → 같은 모양 이용권 줄 2개(하루 이용권·1년권, 「다른 이용권 보기」로 주간·횟수권 펼침) → 금액이 들어간 버튼 하나.
- 무료로 기다리는 길(「내일 다시 채워져요」)을 돈 내는 길보다 먼저 적는다. 버튼에 금액을 넣는다. 가장 큰 글자는 값.
- 특가 취소선·할인율은 2026-11-27 20:45(KST)부터(`saleAnchorAllowed`) — 그 전엔 특가 값과 실제 남은 시간만.
- 무료 1회를 쓰는 버튼(「다른 답장 더 보기」 등)은 누르기 전에 「· 1회」를 적는다(무제한·제한 없음이면 안 적음).

## 도파민 체크리스트 (화면마다)

1. 첫눈에 큰 제목 한 줄 + 그라데이션 면 하나 + 3D 아이콘 하나.

## 1.2 개편 「떠 있는 유리」 (2026-11-08)

사장님 지시: 새 탭 바 결을 이어서 **앱 전체 UI/UX 를 손본다.** 탭 바의 떠 있는 유리·스프링 움직임을 앱의 공통 언어로 넓힌다.

### 바탕과 카드 (토스 결)
- **탭 화면(홈·탐색·마이·연애 연습)과 설정·목록 화면**은 옅은 회색 바탕 `theme.canvas`(#F3F5F9) 위에 **흰 카드 `theme.card`**. `Screen tab` 은 기본 바탕이 canvas 다.
  - canvas 위에 `theme.surface`(연회색)를 바로 놓으면 바탕과 구분이 안 된다 → canvas 위 카드는 `theme.card` + `CardShadow`(다크는 그림자 대신 `theme.separator` 가는 테두리).
  - 흰 카드 **안쪽**의 칩·입력칸·작은 면은 `theme.surface`.
- **읽는 화면(채팅방·결과·결제·안내)** 은 흰 바탕(`theme.background`) 그대로.
- 카드 모서리 22(`Radius.lg + 2`), 큰 카드 28(`Radius.xl`). 카드 안 여백 16~20.
- 설정·목록은 **`ListGroup`**(`components/ui/list-group.tsx`)으로 묶는다 — 흰 카드 하나에 `ListRow` 여러 줄, 줄 사이 가는 선, 아이콘은 앱 색 옅은 바탕에 앱 색(자동).

### 떠 있는 유리
- 공통 부품 **`GlassSurface`**(`components/ui/glass-surface.tsx`): iOS 26+ 는 시스템 유리, 그 밖은 **불투명한** 흰 면(다크 #1C202E) + 가는 테두리 + 위 광택 + 떠 있는 그림자(흐림 없이 반투명으로 두면 0.985 로도 뒤 글자가 뚜렷이 비쳤다). 탭 바·채팅 입력창·스크롤 머리말이 같은 유리를 쓴다.
  - 웹 함정: GlassSurface 안에 TextInput 을 넣으면 웹은 위치 지정 없는 입력칸을 유리 바탕(절대 위치)보다 먼저 그려 글자가 깔린다 → 입력칸에 웹만 `position: 'relative'`(composer 의 PillInput 참고).
- 둥근 구슬(탭 바 새 채팅·채팅 보내기) 색은 `Brand.orb` 하나로.
- **스크롤 유리 머리말**: 큰 제목이 있는 `Screen safeTop` 화면은 `title="마이"` 처럼 넘기면 제목이 사라질 만큼 내렸을 때 작은 제목이 든 유리 띠가 내려온다(`components/ui/glass-header.tsx`). 직접 ScrollView 를 쓰는 화면은 `useScrolledPast(64)` + `<GlassHeader title top visible />`.
- **채팅 입력창**도 떠 있는 유리 알약: [캡처 버튼 | 글 입력 | 보내기 구슬]. 보내기 구슬은 새 채팅 구슬과 같은 그라데이션·광택(보낼 수 있을 때만 색이 찬다). 입력창 위 말투 칩은 한 줄로 가볍게.

### 다크 모드
- 다크는 `theme.card` 와 `theme.surface` 가 같은 색이다 → 흰 카드 **안** 칩·입력칸·눌림 색은 `useInsetFill()`(list-group.tsx, 다크만 surfaceElevated). 공통 Chip 은 다크에서 알아서 한 단계 밝다.
- canvas 위 흰 카드는 `useCardStyle()` / `Card tone="card"` / `ListGroup` / `CardSection` — 라이트는 옅은 그림자, 다크는 가는 테두리.

### 움직임
- 탭 화면은 위에서부터 차례로 살짝 올라오며 등장(`FadeInDown.delay(i*50).springify()` 류, 이미 쓰는 `enter(i)` 패턴).
- 누르는 카드·타일은 `PressableScale`(줄었다 튕김 + 진동). 목록 줄은 눌림 색만.
- 움직임 줄이기 설정(`useReducedMotion`)이면 튕김 없이.

### 하지 말 것
- 기존 기능·문구의 뜻을 바꾸지 않는다(문구는 더 짧고 친근하게 다듬는 정도). 없는 기능을 그리지 않는다.
- 테스트가 찾는 접근성 라벨·testID·문구는 되도록 유지하고, 바꾸면 테스트도 같이 고친다.
- 이모지는 칩 앞 작은 표정 정도. 🚧 같은 뜻이 어긋난 이모지·장식 금지.

## 「AI 티」 덜기 (2026-11-17, 11/12 회의 7번)

팀 피드백: 「UI 는 깔끔해졌지만 아직 AI 티가 많이 남」. 다음을 원인으로 보고 덜었다 — 새 화면도 이 기준으로.
- 그라데이션 카드의 반투명 동그라미 장식(orb) — `HeroCard` 기본 `decor=false`. 꼭 필요한 곳만 켠다.
- 화면마다 떠다니는 3D 이모지 — 화면당 하나 이하, 뜻이 있을 때만(홈 제목 옆 3D 는 뺐다).
- 큰 면마다 파랑→보라 그라데이션 — 화면당 그라데이션 큰 면 하나 이하, 나머지는 흰 카드.
- 같은 배지(「고려대 심리학 연구진이 만든…」) 반복 — 첫 장·결제 화면 정도에만.
- 뻔한 걸 다시 설명하는 부제·되풀이 반짝임 — `GradientButton` shine 은 나타난 뒤 한 번만.
- 큰 제목 30pt 이상 남발 — 첫 장·사용법 24pt, 홈 제목 한 줄 26pt.
- AI 답변도 짧게: 요약 1~2문장, 포인트 2개, 답장 보통 한 문장(`COACH_SYSTEM_PROMPT` 「길이」).
