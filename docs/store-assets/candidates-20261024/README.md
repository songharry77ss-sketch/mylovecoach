## 기본안에서 바꾼 이유

- **읽씹 문구 제거:** 3번 원본의 실제 상황은 함께 찍은 사진을 스토리에 올린 경우입니다. A/B/C는 상황을 단정하지 않는 표현으로, D는 사진을 올린 상황에 맞게 바꿨습니다.
- **온도는 원본에 맞춤:** 1번 채팅의 온도는 `15°`, 4번 보고서는 `25°`이고 기록은 `15° → 25°`입니다. 보고서 시안에는 `25°`를 사용하고, 온도가 항상 오른다고 읽히는 표현 대신 쌓이는 대화와 변화·기록을 강조했습니다.
- **연애 유형으로 설명:** 기본안의 `진짜 연애 MBTI`를 메인 제목에서 줄이고 KKTI의 연애 유형과 컬러를 중심으로 썼습니다. 원본 UI에 있는 `ESFJ`·`MBTI` 문구는 고치지 않았습니다.
- **상황 입력을 실제 화면으로 증명:** 제공된 6번 홈 캡처에는 새 입력 UI가 없으므로 1번 채팅 하단의 실제 `캡처를 올리거나 상황을 적어주세요` 부분을 별도 카드로 잘랐습니다. 홈 화면을 새로 그리거나 기능을 덧그리지 않았습니다.
- **숫자의 의미 유지:** C의 `95%`·`+10°`·`50%`·`25°`에는 답장 성공 확률·연습 피드백·풀이·호감 온도의 **예시**라는 설명을 붙였습니다. `16가지 연애 유형`은 [앱 설명](../../STORE_LISTING.md)의 기존 기능 설명에 근거합니다. 모든 이용자에게 같은 결과가 나온다는 주장이나 보장 문구는 넣지 않았습니다.
- **시안별 말투 차별화:** A는 짧고 직접적인 문구, B는 밤의 고민에 공감하는 문구, C는 기능과 수치를 설명하는 문구, D는 다음 장으로 이어지는 대화체로 구성했습니다.

## 입력과 원본 보존

- 이미지 입력은 `docs/store-assets/ios-6.7/1-chat-replies.png`부터 `6-home.png`까지 기존 앱 캡처 6장입니다. 각 카드의 원본과 좌표는 두 Python 스크립트의 `CROPS`에 있습니다.
- `1번`: 호감 온도 `15°`, 호칭 `언니`, 존댓말 유지, 성공 확률 `95%`, 실제 답장과 예상 반응, 상황 입력창
- `2번`: 민지와의 소개팅 후 약속 대화, 실제 코치 피드백 `+10°`
- `3번`: 사진을 올린 상황에 대한 생각과 가능성 `50% / 30% / 20%`
- `4번`: 수연의 보고서 `25°`, 분석 `2회`, 온도 기록 `15° → 25°`, 한 줄 요약
- `5번`: `직진 불도저` 결과, `노을 코랄`·`ESFJ`·`2번 조력가`; 아래 X·Threads 공유 로고 영역은 사용하지 않음
- `6번`: 연애 연습·속마음 카드·비밀 상담·KKTI 테스트의 실제 홈 카드
- 레퍼런스 보드는 첨부 이미지로 분위기와 구성만 참고했습니다. 보드 파일·타사 앱 화면·로고·캐릭터·사진은 이 폴더에 복사하거나 시안에 넣지 않았습니다.
- 앱 코드, 기존 캡처·프레임 이미지, 아이콘·그래픽은 변경하지 않았습니다. 새 장식은 Pillow의 선·도형으로 만든 그래픽이며, UI 내용은 원본 크롭·균등 확대·회전만 사용했습니다.

## 생성한 파일

```text
candidates-20261024/
  README.md
  make_candidates.py
  layout_d.py
  index.html
  validation.json
  overview.png
  overview-play.png
  A/  B/  C/  D/                 # 각 폴더에 아래 14개 이미지
    1.png … 6.png               # 1290×2796, iOS 6장
    play-1.png … play-6.png     # 1242×2208, Play 6장
    contact.png                # iOS 6장 가로 비교, 높이 900px
    contact-play.png           # Play 6장 가로 비교, 높이 900px
```

스토어용 PNG는 **48장**(iOS 24장 + Play 24장), 시안별 비교 PNG **8장**, 첫 장 비교 PNG **2장**입니다. Play는 별도 배치를 만든 뒤 1242×2208의 9:16으로 출력하므로 iOS 이미지를 세로로 찌그러뜨린 결과가 아닙니다.

`index.html`은 로컬 이미지로만 구성한 비교 페이지입니다. `validation.json`은 크기·색상 모드·용량·입력 SHA-256, 텍스트와 크롭 배치 등의 생성 검증 기록입니다. 실제 문구의 잘림·겹침과 D 리본 연결은 비교 이미지 및 개별 이미지의 시각 검토도 함께 수행했습니다.

## 다시 만들기

이 PC의 Python, Pillow **12.1.1**, 저장소의 Pretendard Bold/Medium OTF만 사용합니다. 다운로드·네트워크·브라우저·추가 패키지 설치는 필요하지 않습니다.

저장소 루트에서:

```powershell
python docs/store-assets/candidates-20261024/make_candidates.py
```

일부 시안만 다시 만들 때:

```powershell
python docs/store-assets/candidates-20261024/make_candidates.py --styles A
```

전체 재생성 시 기존 **이 후보 폴더의 생성물**을 갱신합니다. 입력 경로는 스크립트 위치를 기준으로 계산하므로 작업 디렉터리에 의존하지 않습니다. 재생성 가능한 전체 검증 기록이 필요하면 옵션 없이 4종 모두 실행해 주세요.

글꼴 입력:

- `api/_assets/fonts/Pretendard-Bold.otf`
- `api/_assets/fonts/Pretendard-Medium.otf`
- 글꼴 라이선스: `api/_assets/fonts/OFL.txt`

검증은 스크립트의 `validate()`에서 iOS/Play 각 24장의 크기, RGB 모드, PNG 읽기, 장당 3,000,000바이트 이하를 확인합니다. 제목은 1290px 작업 폭 기준 110px 이상으로 만들었습니다. Play는 같은 작업 폭에서 높이를 별도 구성한 후 최종 크기로 비례 축소합니다.
