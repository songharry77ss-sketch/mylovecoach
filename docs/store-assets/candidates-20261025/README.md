## 시안과 사진

- **P:** Bumble 보드의 전면 인물 사진·큰 제목·확대 카드 구성만 참고했습니다. 카페 여성 → 소파 남성 → 스탠드 여성 → 강변 커플 → 남녀 친구 → 소파 남성 순서입니다. 따뜻한 브라운 그림자, 흰 제목, 노랑 `#FFE786` 강조입니다. 얼굴 표정이 목업에 가리지 않도록 장별 사진 위치를 조정했습니다.
- **S:** Instagram 보드의 스티커와 듀오링고 보드의 장별 색 변화만 참고했습니다. 마젠타 `#940051`, 보라 `#4E21BD`, 블루 `#005C85`, 코랄 `#9D300E`, 코발트 `#3444AA`, 그린 `#00634E` 바탕에 노랑 `#FFF18E`를 강조했습니다. 여성·남성 스튜디오 사진을 교대로 둥근 말풍선 안에 넣었습니다. 장식은 새로 그린 SVG이며 타사 캐릭터·로고가 아닙니다.
- **N:** BeReal 보드의 검정과 Character.AI 보드의 네온 분위기만 참고했습니다. 네온 거리 남성 → 소파 남성 → 스탠드 여성 → 해 질 무렵 커플 → 저녁 카페 친구 → 네온 거리 남성 순서입니다. 검정 `#080911`, 연분홍 `#F5A6FF` 강조, 다층 보라 광원과 유리 캡션을 사용했습니다.

사진은 내장 `image_gen` 도구로 한 장씩 **8장** 새로 생성했습니다. 모두 1024×1536 PNG이며 생성 결과를 그대로 복사했습니다. 25–28세 한국인 가상 성인, 단정한 일상복, 실존 인물·연예인 비참조, 노출·선정적 포즈 없음, 휴대폰 화면 비노출 조건을 프롬프트에 넣었습니다. 커플·친구를 포함해 남성 5명·여성 5명이 등장합니다. 손·눈·치아, 복장과 휴대폰 방향을 생성 직후 시각 검토했습니다.

정확한 프롬프트와 생성 원본 경로는 [_photos/prompts.md](_photos/prompts.md)에 있습니다. 레퍼런스 보드 파일은 저장소에 복사하지 않았고, 해당 앱의 화면·인물·로고를 입력 또는 합성에 사용하지 않았습니다.

## 최종 카피

세 시안의 문구를 통일해 시각 방향을 비교할 수 있도록 했습니다. `/`는 줄바꿈입니다.

| 장 | 제목 | 보조 문구 | 확대 UI |
|---|---|---|---|
| 1 | 뭐라고 답장하지? / 캡처 한 장이면 끝 | 호칭·말투 그대로, 답장 3가지 | 실제 답장과 성공 확률 95% |
| 2 | 실전 전에 / AI랑 카톡 연습 | 보낼 때마다 코치가 바로 피드백 | 연습 말풍선과 +10° 피드백 |
| 3 | 그 사람 속마음 / 가능성은 몇 %? | 하나의 상황을 여러 가능성으로 | 실제 50%·30%·20% 풀이 |
| 4 | 대화 속에 담긴 / 우리 호감 온도 | 온도 변화부터 상대 분석 보고서까지 | 실제 수연 보고서 25° |
| 5 | 카톡 습관 속 / 나의 연애 유형 | 16가지 유형 · 나만의 연애 컬러 | 실제 KKTI 직진 불도저 결과 |
| 6 | 캡처 없이 / 상황만 적어도 OK | 연습·속마음·비밀 상담까지 한 앱에 | 실제 홈 메뉴와 상황 입력창 |

작업서에서 조정한 이유:

- 3번 원본은 함께 찍은 사진을 올린 상황이므로 `읽씹`을 제거했습니다. 원본의 풀이처럼 가능성을 설명합니다.
- 4번은 호감이 항상 오른다고 보장하지 않고, 대화에 담긴 온도와 변화를 보여줍니다. 원본의 25°와 기록을 그대로 사용했습니다.
- 5번은 `진짜 연애 MBTI` 대신 KKTI의 연애 유형·컬러를 중심으로 짧게 썼습니다. 원본 캡처의 MBTI 문구는 변경하지 않았습니다.
- 6번 원본 홈에는 상황 입력창이 없으므로 1번 원본 하단의 실제 입력창을 추가로 크롭했습니다. 없는 UI를 그려 넣지 않았습니다.

합성은 모두 **HTML/CSS**입니다. 원본 `docs/store-assets/ios-6.7/1-chat-replies.png`부터 `6-home.png`를 직접 참조하며, 카드도 CSS 뷰포트로 원본 일부를 균등 확대했습니다. 검은 베젤·다이내믹 아일랜드·둥근 모서리, 다층 그림자·radial-gradient 광원·backdrop-filter 캡션을 CSS로 구성했습니다. UI의 글자·숫자·기능은 새로 그리지 않았습니다. KKTI의 X·Threads 공유 로고 부분은 확대 카드가 덮는 배치입니다.

글꼴은 저장소의 `Pretendard-Bold.otf`와 `Pretendard-Medium.otf`를 `file:///` URL로 불러옵니다. 제목은 디자인 폭 1290 기준 134–140px, 각 줄 14자 이내이며 위쪽 30% 안에 있습니다. Play는 같은 HTML의 미디어 쿼리로 사진·목업·카드 크기와 위치를 재배치하므로 iOS 이미지를 늘이거나 찌그러뜨리지 않습니다.

## 재생성

저장소 루트에서 순서대로 실행합니다. 기존 앱·원본·1차 결과는 읽기만 하며, 재생성 시 이 2차 후보 폴더의 생성물만 갱신합니다.

```powershell
python docs/store-assets/candidates-20261025/build.py
powershell -ExecutionPolicy Bypass -File docs/store-assets/candidates-20261025/render-all.ps1
node docs/store-assets/candidates-20261025/validate.mjs
node docs/store-assets/candidates-20261025/contrast_audit.mjs
python docs/store-assets/candidates-20261025/optimize_validate.py
```

`render-all.ps1`은 사용자 지정 `C:/Users/shsop/mylovecoach-codex-tools/render.mjs`를 수정하지 않고 호출합니다. Windows Edge와 준비된 playwright-core만 사용했습니다. `optimize_validate.py`는 3MB 이하 파일을 변경하지 않으며, 초과할 때만 무손실 압축 후 필요 시 256색 PNG 최적화를 수행하도록 준비했습니다.

## 확인 결과

- **렌더 성공:** 지정 Edge `render.mjs`로 iOS 18장·Play 18장, 비교 이미지 11장을 모두 렌더했습니다. 샌드박스 차단·렌더 오류는 없었습니다.
- **PNG 규격:** 사진 8장 + 스토어 36장 + 비교 11장 = 총 55개 PNG. 모든 파일이 3,000,000바이트 이하입니다. 최대 2,232,028바이트이며 추가 압축·팔레트 양자화 없이 렌더된 RGB PNG를 보존했습니다.
- **브라우저 검증:** 36/36 구성이 통과했습니다. Pretendard 로딩·이미지 로딩·제목 두 줄 실제 범위·14자 이하·상단 30%·상단 150px/하단 120px 안전 여백을 확인했습니다. 회전된 목업의 실제 바운딩 박스 높이는 iOS 57.14–62.03%, Play 59.59–62.18%입니다.
- **명암 대비:** 36개 구성의 제목 두 줄·강조어·보조 문구 총 144개 영역에서 글자를 잠시 숨긴 실제 합성 배경을 픽셀 단위로 측정했습니다. 최저 대비 **5.6056:1**, 4.5:1 미만 영역 0개입니다. QA용 임시 이미지 144개는 측정 후 개별 삭제했으며 결과 PNG는 변경하지 않았습니다.
- **원본 보존:** 캡처 6장의 SHA-256이 제작 시작 시 기록과 모두 일치합니다. 확대 UI 카드의 모든 이미지가 원본 캡처를 참조합니다.
- **시각 검토:** 각 시안의 iOS·Play 비교 이미지와 폭 230px 비교에서 제목 가독성과 배치를 확인했습니다. 첫 장, 크롭이 큰 3번, KKTI 5번, 상황 입력 6번 등은 개별 크기로 추가 확인했습니다. 5번 iOS·Play 총 6개에서 X·Threads 공유 로고가 전면 카드 뒤로 가려진 것도 확인했습니다.
- **조정:** P의 얼굴 가림·사진 경계와 Play 하단 목업 여백을 다듬고, N의 사진을 밝게 조정해 얼굴 표정을 살렸습니다.

스토어 업로드·서버 변경·git add·커밋·push는 하지 않았습니다. 앱 코드·기존 캡처·1차 작업서·1차 결과도 수정하지 않았습니다.
